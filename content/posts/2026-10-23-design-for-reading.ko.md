기술 블로그 디자인의 목적은 복잡한 내용을 읽기 쉽게 만드는 것이며, 이를 위해 필요한 것은 장식이 아닌 질서입니다. 이 블로그를 읽기 어려웠던 원인, 디자이너와 타이포그래퍼의 기준, 앞으로 적용할 디자인 가치를 정리하였습니다.

## 1. 뛰어난 디자이너의 기준

### 가. 디터 람스: 적게, 그러나 더 낫게

디터 람스는 수십 년간 브라운(Braun)의 제품을 디자인하였으며, 그의 [좋은 디자인의 10가지 원칙](https://vitsoe.com/gb/about/good-design)은 디자인 분야에서 가장 많이 인용되는 원칙 중 하나입니다. 이 중 블로그에 직접 적용되는 원칙은 다음 5가지입니다.

- ‘좋은 디자인은 제품을 유용하게 한다’: 블로그의 용도는 읽기이며, 나머지는 부차적임
- ‘좋은 디자인은 제품의 이해를 돕는다’: 가장 좋은 디자인은 설명이 필요 없음. 독자가 다음에 볼 곳을 고민하지 않아야 함
- ‘좋은 디자인은 눈에 띄지 않는다’: 디자인보다 내용이 먼저 보여야 함
- ‘좋은 디자인은 마지막 디테일까지 빈틈없다’: 람스는 “어떤 것도 임의로 정하거나 우연에 맡겨서는 안 된다”라고 말함
- ‘좋은 디자인은 가능한 한 최소한으로 디자인한다’: 람스는 이를 “Less, but better(적게, 그러나 더 낫게)”의 세 단어로 요약

### 나. 조니 아이브: 단순함은 질서

조니 아이브는 오랫동안 애플의 디자인을 이끌었으며, 2013년 iOS 7을 발표하면서 단순함을 다음과 같이 설명하였습니다.

> “진정한 단순함은 어수선함과 장식이 없다는 것보다 훨씬 더 많은 것에서 나온다.”

또한 단순함은 “복잡함에 질서를 부여하는 것”이라고 하였습니다([TechRadar](https://www.techradar.com/pro/quote-of-the-day-by-former-apple-design-chief-jony-ive-true-simplicity-is-derived-from-so-much-more-than-just-the-absence-of-clutter-and-ornamentation-laying-the-foundation-for-a-timeless-design-philosophy)).

기술 블로그에서는 이 관점이 중요합니다. 이 블로그의 글은 제어 루프, 신호, 가스 흐름을 다루므로 내용을 덜어 내는 방식으로는 단순하게 만들 수 없습니다. 가능한 방법은 본문을 따라가는 경로를 명확히 하고, 각 그림을 해당 설명 문단 바로 옆에 배치하여 질서를 세우는 것입니다.

아이브는 2025년 [Stripe Sessions](https://stripe.com/sessions/2025/a-conversation-with-sir-jony-ive) 대담에서 정성에 관해서도 언급하였습니다. 아무도 보지 않을 수납장 안쪽까지 마감하는 가구 장인을 예로 들며 “사람으로서 우리가 얼마나 발전했는지는 아무도 보지 않을 때 하는 일에서 드러난다”라고 말하였습니다([Jim Nielsen의 메모](https://blog.jim-nielsen.com/2025/notes-from-interview-with-jony-ive/)에 기록된 내용). 웹 페이지에서 수납장 안쪽에 해당하는 요소는 대체 텍스트, 줄바꿈, 다크 모드입니다.

## 2. 타이포그래퍼의 기준

읽기 위한 사이트에서는 타이포그래피가 가장 중요한 디자인 결정입니다. Matthew Butterick과 Robert Bringhurst는 다음과 같은 수치 기준을 제시합니다.

<표 1> 본문 타이포그래피 기준

| 항목 | Matthew Butterick | Robert Bringhurst |
|---|---|---|
| 한 줄 글자 수 | 45~90자 | 45~75자, 이상적 길이 66자 |
| 웹 본문 글자 크기 | 15~25픽셀 | |
| 줄 간격 | 글자 크기의 120~145&nbsp;% | |

Butterick의 첫 번째 규칙은 “본문이 먼저”이며, 문서의 품질은 대부분 본문의 형태에 달려 있다는 의미입니다([Practical Typography](https://practicaltypography.com/typography-in-ten-minutes.html)). Bringhurst의 수치는 *The Elements of Typographic Style*에 수록된 값입니다([인용 출처](https://webtypography.net/2.1.2)).

## 3. 뛰어난 기술 사이트 사례

- Bartosz Ciechanowski: [GPS](https://ciechanow.ski/gps/) 등의 작동 원리를 길게 설명. 인터랙티브 다이어그램을 해당 설명 바로 옆에 배치
- Edward Tufte: 강의 자료가 단순함. 정돈된 본문, 여백 주석, 본문과 통합된 차트로 구성. [Tufte CSS](https://github.com/edwardtufte/tufte-css)가 이 형식을 웹에 구현
- Gwern Branwen: 미니멀리즘, 좋은 타이포그래피, 흑백, 여백 주석으로 구성. 링크한 페이지의 사본을 보관해 링크가 계속 작동하도록 유지([Design](https://gwern.net/design))
- Julia Evans: 아는 것과 모르는 것을 솔직하게 기술. 처음 시작할 때 있었으면 좋았을 글을 작성([Blogging principles](https://jvns.ca/blog/2017/03/20/blogging-principles/))

위 사이트는 모두 장식 없이, 견고한 본문 단과 독자가 필요로 하는 위치에 배치한 그림으로 질서를 구성합니다.

## 4. 이 블로그의 문제

브라우저에서 글 페이지를 측정하였습니다.

[그림 1] 이전 디자인

![이전 디자인. 왼쪽에 좁은 날짜 열이 있고 본문 열은 한참 오른쪽에서 시작합니다. 본문 앞에 요약 문구가 달린 라벨 3개가 있습니다.](/images/design-before.png)

1. 줄이 너무 김: 넓은 화면에서 한 줄이 영문 기준 평균 83자, 최대 89자. Bringhurst의 기준 범위 45~75자 초과
2. 본문이 중앙에서 벗어남: 왼쪽 열에는 날짜와 읽는 시간만 있고, 본문 열은 화면 중앙보다 한참 오른쪽에서 시작
3. 요약을 읽기 어려움: 요약 라벨이 옆 열을 차지해 휴대폰에서는 요약 문구 한 줄이 약 30자로 줄어듦. 요약의 시각적 비중도 본문과 같음
4. 차트가 너무 작고 밝음: 본문과 같은 너비여서 라벨 글자가 작고, 다크 모드에서 밝은 흰색 사각형으로 표시됨

## 5. 디자인 가치

1. 읽기 우선: 모든 디자인 결정은 본문에서 시작
2. 장식 대신 질서: 단 1개, 명확한 제목 위계, 그림은 해당 문단 옆에 배치
3. 최소한의 디자인: 서체 패밀리 1개, 회색 계조, 상태 표시용 색 1개. 애니메이션과 자바스크립트 미사용
4. 아무도 보지 않는 세부까지 정성: 숫자와 단위를 다른 줄로 분리하지 않음. 모든 그림에 텍스트 설명 제공. 차트는 다크 모드에 맞춰 표시
5. 정직: 모든 수치에 조건을 함께 기재. 글마다 잘못 판단한 점 기재
6. 장기 사용: 기본 HTML과 CSS 사용. 이듬해에 낡아 보일 유행은 따르지 않음

![새 디자인. 가운데 정렬된 단 1개로 구성되며, 날짜는 제목 위에, 요약 라벨은 해당 문구 위에 있습니다.](/images/design-after.png)

<표 2> 디자인 변경 전후 비교

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 넓은 화면의 한 줄 글자 수(영문) | 평균 83자 | 평균 67자 |
| 글자 크기 | 17픽셀 | 18픽셀(휴대폰 17픽셀) |
| 레이아웃 | 날짜 열과 본문 열 | 가운데 정렬 단 1개, 날짜는 제목 위 |
| 요약 | 옆 열에 라벨 | 문구 위에 라벨, 왼쪽에 가는 선 |
| 차트 | 본문 너비, 다크 모드에서 흰색 | 최대 46 rem 너비, 다크 모드에서 색 반전 |

추후 2가지를 추가로 변경할 계획입니다. 넓은 화면에서는 Tufte와 Gwern의 방식처럼 출처를 여백 주석으로 옮기고, 차트는 페이지 색을 정확히 따르도록 SVG 파일로 변경하겠습니다.

## 7. 잘못 판단한 점

- 줄 길이를 처음에 한국어 본문 기준(한 줄에 한글 약 36자)으로 설정함. 블로그를 영어로 다시 작성하면서 줄 길이를 다시 측정하지 않아, 같은 너비에 영문 83자가 들어감
- 날짜 열을 실험 노트 한 페이지라는 아이디어에서 출발해 설계함. 독자의 필요에서 출발하지 않음

## 8. 요약

- 기술 블로그는 읽기를 기준으로 디자인. 본문이 우선
- 단순함은 요소를 덜어 내는 것이 아니라 복잡한 내용에 질서를 부여하는 것
- 측정된 기준 사용: 한 줄에 약 45~75자, 이상적 길이 66자
- 정성은 아무도 보지 않는 세부에서 드러남
